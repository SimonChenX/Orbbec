## 1. 骨骼分析（彩色画面 → 33 个关键点）

### 结论先说
* **能做**，服务器侧独立进程 `ob-pose`（Python + mediapipe PoseLandmarker），约 **41ms/帧**，
  默认 **8fps**（约占半个核，服务器 56 核很轻松）。
* ⚠️ **不塞进 ob-hub**：推理依赖重、会崩，独立进程崩了不影响主服务，`systemctl stop ob-pose` 就彻底停掉。

### 数据流（全走本机回环）
```
ob-hub /snapshot/color.jpg ──拉──> ob-pose ──mediapipe──> POST /api/hub /api/pose
                                                            │
浏览器 <canvas> 画骨架 <────────── GET /api/pose ────────────┘
```
前端把 33 个归一化关键点画在**彩色画面上的透明 canvas**（`position:absolute` 精确覆盖），
所以骨架永远和画面同步缩放，不需要服务器重新编码图像。

### 关键实现点
* 侧车拉 `?x=&y=` 快照而不是订阅 MJPEG：省事、可随时重启、不和观众抢流。
* 前端画骨架要**先描一层深色粗线再画亮线**，否则浅色背景上看不清。
* `visibility < 0.35` 的点不画 —— 人坐在桌子后面时，模型会外推腿部关键点（y 甚至 >1），
  照画会出现"飘在空中的腿"。
* hub 只保留**最新一帧**，超过 3 秒没更新就返回 `present:false`（防止画面停了骨架还挂着）。

### 已知局限
* 单人（`num_poses=1`）；遮挡场景（坐姿、桌子挡腿）下半身关键点不可信，属正常。
* 8fps 是按需定的；`OB_POSE_FPS` 调大更跟手，代价是 CPU。

## 2. 红外画面（IR）

### ⚠️ 先说最重要的一条：**它测不了温度**
Astra Pro Plus 的"红外"是 **850nm 近红外补光相机**，拍的是**反射率**（相当于一台黑白相机
配红外灯），设备里**没有热像传感器**。所以：

* 能做：红外灰度画面、强度统计（中位强度/强反射区/亮部占比，0~1023）。
* **不能做：温度。** 要温度得另配热像仪（MLX90640 / FLIR Lepton 之类）。
* 网页上已明确标注「850nm 近红外反射 · 非热成像，无温度」，避免同事误读。

### ✅ 更正：**深度和红外「可以」同时出图**（早期结论是错的）
早期只把两条流 `enable` 到**同一个 pipeline** 里，结果深度正常、IR 恒 0 帧：

```
同一个 pipeline 里 enable 两条流：深度 29.1 fps 正常    IR：0 帧
```

据此得出了「共用 IR 传感器、只能二选一」的结论 —— **这个结论是错的**。
2026-10-14 复核发现：**各开一条独立 pipeline**（各自 `start_with_config`）就能同时满帧：

```
两条独立 pipeline：深度 29.3 fps    红外 29.3 fps   ← 同时、满帧
```

所以现在采集端默认**两路都开**（`OB_RELAY_DEPTH=1` / `OB_RELAY_IR=1`，网页可关），
页面布局为 左侧彩色（含骨骼）/ 右上深度 / 右下红外。

> 📌 教训：**「A 和 B 互斥」这种结论，要说清是在什么配置下测的。**
> 同一个 pipeline 内 enable ≠ 两条独立 pipeline。换个实现方式再测一次很便宜。

### 带宽提醒
红外是 10bit 噪声数据，zlib 只压到 **1.5×**（深度是 7.2×），所以两路同开时入站约
**144 Mbps**（红外占绝大部分），采集端约 1.7% 掉帧。链路吃紧时可在网页上把红外关掉。

### ⚠️ 第三条：**IR 只有 640x480 出图**
| IR 档位 | 实测 |
|---|---|
| 320x240 | 档位列表里有、能起流，但**永远等不到 frameset（0 帧）** |
| **640x480** | ✅ 29fps，`data_size=614400` |

（和深度刚好反过来 —— 深度只有 320x240 可用。**这设备的档位表和实际能力完全对不上，
任何档位都要用真实抓帧验证过才能信。**）

### 渲染
服务端做「灰度 + 2%~98% 分位拉伸」，分位用 **1024 桶直方图**求
（IR 是 10bit，别去排序 30 万个值 —— 那样只能跑到 ~20fps，改成直方图后 26.7fps）。

## 3. 深度取点（鼠标读某点深度）

* 后端 `/api/depth_at?x=&y=`（x/y 是**深度图像素坐标**）：
  hub 留了一份最近的原始 uint16 帧，直接查内存，返回 `value / mm / valid / age_ms`。
* 前端：鼠标在深度图上移动 → 换算到 320x240 坐标 → 70ms 节流请求 → 十字标记 + 数值跟随，
  无效点标红并提示"该点无有效深度"。

### ⚠️ 深度单位：SDK 报的 valueScale 不可信
SDK 文档写「毫米 = 像素值 × valueScale」，本机 `valueScale` 报 **1.0**，但那样会得到
「人 61mm、背景 238mm」—— 人离相机 6cm 不可能。用**距离比值**判定：

```
原始最远/最近 = 238 / 61 = 3.9
真实场景（人约 0.8m、背景约 3.1m）比值 ≈ 3.9   ✅ 吻合
⇒ 原始单位是「厘米」，×10 得毫米
```

换算后实测变成「中心 894mm、最近 570mm、最远 2390mm」，和办公场景完全吻合。

**这个系数做成了可标定参数**：`/etc/default/ob-hub` 里的 `OB_HUB_DEPTH_MM_PER_UNIT`（默认 10）。
现场拿卷尺量一个已知距离对一下，不符就改这个数。

## 4. 本机直连模式（相机直接插到服务器上，不走网络）

老板后续会把相机从树莓派上拔下来，直接插到另一台服务器本地用。架构上**不用改代码**：

```
树莓派模式：  Pi(ob-relay) ──TCP──> 服务器(ob-hub)        数据过网络
本机直连：    服务器(ob-relay→127.0.0.1) ──回环──> ob-hub   不占网络
```

* 安装：`sh deploy/install-relay.sh --local`
  （会把 `OB_RELAY_HOST` 改成 `127.0.0.1`，并自检 ffmpeg / v4l2-ctl / SDK 是否齐全）
* PSK：本机模式下从 `/etc/default/ob-hub` 的 `OB_HUB_PSK` 抄一份到 `/etc/default/ob-relay` 即可。
* 依赖：`ffmpeg`、`v4l-utils`、`python3`、**x86_64 版 Orbbec SDK**
  （官方 releases 下 linux_x64，解到 `/opt/orbbec/SDK`；树莓派那份是 aarch64 的，不能混用）。
* hub 侧零改动：入站 `:9501` 本来就在本机监听，回环连接和远程连接走的是同一套代码路径。

## 5. 本轮踩的坑（都很费时间，记下来）

1. **nginx 漏代理新接口**：宝塔的 extension 里原本只写了 `/api/status`、`/api/config` 两条
   `location =`，新增的 `/api/pose`、`/api/depth_at`、`/ir.mjpg` **全 404** → 骨骼一直不显示。
   已改成 `location ^~ /api/` 通配，以后加接口不用再动 nginx。
   * 另外：本机 nginx 是**宝塔那套**，`systemctl reload nginx` 会报
     `nginx.service is not active`，要用 `/www/server/nginx/sbin/nginx -s reload`。
2. **`import zlib` 漏了** → 深度线程直接抛异常、整路挂掉。
3. **lambda 塞进 JSON**：`json.dumps(回执)` 抛异常 → 控制线程死掉、通道静默失联。
   回执序列化必须 try/except 兜底。
4. **控制通道被读超时掐断** → 平时静默的通道两端都要保活（relay 10s keepalive / hub 90s 判死）。
5. **`[hidden]` 被 `display:flex` 盖掉**：`.grp{display:flex}` 让 `hidden` 失效 →
   红外模式下深度统计没隐藏。加 `[hidden]{display:none!important}`。
6. **无头截图三个坑**（写成了 `/tmp/shot.sh`）：
   * 会话里残留的 `http_proxy` 会被 chromium 继承 → 内网域名被送去海外代理 → 白屏；
   * chromium 148 默认 HTTPS-First，先试 `https://` 内网站点，自签证书握手失败；
   * 默认 profile 一旦被残留实例搞脏 → **永远白屏**，必须每次用全新 `--user-data-dir`；
   * 截图要用 `--virtual-time-budget` 等页面画出来，`--timeout` 会在首帧前拍成白屏。
   * MJPEG 长连接让 headless 的"加载完成"永不触发 → 页面加了 `?snap=1` 静态模式
     （每秒拉快照，顺带也方便弱网/嵌入场景）。
7. **`pkill -9 -f chromium` 会杀掉自己的 shell**（命令行里含 "chromium"）→
   用 `[c]hromium` 且把 pkill 和调用分到不同脚本里。
