# 04 · 已踩过的坑与排障

按「踩坑顺序」记录，每条含**现象 / 根因 / 处理 / 是否已解决**。

## 坑 1 · 以为是「一个相机」，其实是两个

**现象**：按常规思路找 `/dev/video*` 抓深度，抓不到。

**根因**：Astra Pro Plus 在 USB 上是**两个独立设备**：
彩色 = `2bc5:0501`（标准 UVC），深度/IR = `2bc5:0403`（私有协议，**没有 video 节点**）。

**处理**：彩色走 `/dev/video0`，深度/IR 走 SDK。见 [`01-硬件与环境.md`](01-硬件与环境.md) §2。

**状态**：✅ 已解决（认知问题）

---

## 坑 2 · 深度数值看着「太近」（7~26cm）

**现象**：首跑深度，得到 `74~244mm`，均值 `198mm` —— 房间场景不可能这么近。

**根因**：**没乘 `valueScale`**。SDK 原始像素值必须乘 `ob_depth_frame_get_value_scale()` 才是真实单位。

**处理**：`mm = raw * scale`。见 [`03-深度与IR-SDK.md`](03-深度与IR-SDK.md) §5。

**状态**：✅ 已修正（但**量程是否合理仍未定案**，见 [`05-未决问题.md`](05-未决问题.md) §2）

---

## 坑 3 · 深度只出 160x120，不是想要的 640x480

**现象**：首版脚本自动挑到了最小的 profile。

**根因**：没做分辨率选择，默认取了列表第一项。

**处理**：显式优先选 `640x480`，否则取像素数最大的一档：

```python
pick = next((c for c in cands if (c[2], c[3]) == (640, 480)), None)
if pick is None:
    pick = max(cands, key=lambda c: c[2] * c[3])
```

**状态**：✅ 已解决

## 坑 4 · ⭐ 官方 `SaveToDisk` 彩色失败（最费时的坑）

**现象**：

```
[error] Match openni video mode failed!  (OpenNIVideoSensor.cpp:430)
[error] Start stream failed, OB_SENSOR_COLOR
Match openni video mode failed
terminate called after throwing an instance of 'std::runtime_error'
```

`pipeline.start()` 直接抛异常。

**根因**：`OrbbecSDKConfig_v1.0.xml` 的 `<AstraProPlus>` 段里
彩色写的是 **`MJPG 640x480@30`**，而该设备 **SDK/OpenNI 侧只提供 `UYVY`**
（`160x120 / 640x480 / 1280x720 / 1280x800 @30 UYVY`，**根本没有 MJPG**）→ 匹配不上。

> 注意区分：**UVC 侧**（内核 `uvcvideo`）MJPG 是有的且 720p@30；
> 但 **SDK 的 OpenNI 彩色侧**看不到 MJPG。两个栈看到的格式集不一样。

**尝试过但全部无效的修法**（别重复走）：

| 尝试 | 结果 |
|---|---|
| 改 config `<AstraProPlus><Color><Format>` MJPG → UYVY | ❌ 仍报同样错误 |
| 改全局 `<LinuxUVCBackend>` `Auto` → `V4L2` | ❌ 无效 |
| 用 `<ProfileFilter>` 屏蔽全部彩色 profile，逼 `SaveToDisk` 降级纯深度 | ❌ 未生效（彩色仍走 OpenNI 侧） |
| 还原 config 到原始状态 | ✅ 已还原（**当前 config 是干净的**） |

**最终绕法**：
- **深度/IR**：自写 `ob_depth.py` / `ob_ir.py`，pipeline **只开一个传感器** → 完全绕开彩色匹配问题
- **彩色**：走 UVC `/dev/video0`

**状态**：✅ 已绕过（**SDK 侧彩色的根本修复未做**，见 [`05-未决问题.md`](05-未决问题.md) §3）

## 坑 5 · SDK 找不到 config

**现象**：在别的目录跑脚本，行为异常 / 参数不生效。

**根因**：SDK 从**当前工作目录**找 `OrbbecSDKConfig_v1.0.xml`。

**处理**：**必须** `cd /opt/orbbec/Example/bin` 再跑。

**状态**：✅ 已解决（写进了 README 铁律）

---

## 坑 6 · `LD_LIBRARY_PATH` 没设

**现象**：`OSError: libOrbbecSDK.so: cannot open shared object file`

**处理**：`LD_LIBRARY_PATH=/opt/orbbec/SDK/lib`。

**状态**：✅ 已解决

---

## 坑 7 · 直方图分桶全是 0（脚本自身的小 bug）

**现象**：`summary.json` 里 `hist_mm` 恒为 `{"0": <全部像素>}`。

**根因**：`ob_depth.py` 里分桶写的是 `int(v // 500) * 500` ——
当所有值 < 500 时全部落进 `0` 桶（**想表达的是 500mm 一档**）。

**影响**：**仅影响直方图统计**，不影响 `min/max/mean` 和图像。

**建议修法**：改成 50mm 分桶，例如 `int(v // 50) * 50`。

**状态**：⚠️ **未修**（低优先级；接手时顺手改掉即可）

## 排障决策树

```
抓不到图
├─ lsusb 里没有 2bc5:0501 / 2bc5:0403 ？
│   └─ USB 没插好 / 供电不足（换口、用带供电的 hub）
├─ 彩色抓不到
│   ├─ "Device or resource busy" → fuser -v /dev/video0，杀占用进程
│   ├─ 全黑/全绿 → 显式 -input_format mjpeg
│   └─ 帧率低 → 同上（协商成了 YUYV）
└─ 深度/IR 抓不到
    ├─ "cannot open shared object" → 设 LD_LIBRARY_PATH
    ├─ 参数不生效 / 异常 → 是否 cd 到 Example/bin
    ├─ "Match openni video mode failed" → 别开彩色！只开单传感器（见坑 4）
    └─ 深度全 0 → 物体超出量程（<0.6m 或 >8m），或者没乘 valueScale
```

## 一条经验

> **别从外部猜 SDK 为什么报错，先看它的日志。**
> SDK 会往 stderr 打非常详细的分级日志（`[info]` / `[warning]` / `[error]`，
> 含**文件名:行号**）。本次坑 4 的根因就是从 `OpenNIVideoSensor.cpp:430` 定位的。
>
> ```bash
> ... python3 ob_depth.py 2> run.log   # 把日志单独收起来
> grep -aiE "error|failed|warning" run.log
> ```
