## 2. 相机在 USB 上的真面目：**两个独立设备**

这是本项目**最重要的一条认知**。插上后 `lsusb` 会看到**两个** Orbbec 设备：

```
Bus 001 Device 055: ID 2bc5:0501  Orbbec  Astra Pro HD Camera
Bus 001 Device 056: ID 2bc5:0403  Orbbec  Astra Pro
```

| VID:PID | 名称 | 承载 | 驱动栈 | 设备节点 |
|---|---|---|---|---|
| **`2bc5:0501`** | Astra Pro **HD Camera** | **彩色** | 标准 **UVC**（内核 `uvcvideo`） | `/dev/video0`、`/dev/video1` |
| **`2bc5:0403`** | Astra Pro | **深度 + IR** | 厂商**私有协议**（Vendor Specific Class） | 无 video 节点；经 SDK/OpenNI2 访问 |

**推论（务必记住）：**

- **彩色完全不需要 SDK** —— 它就是个标准 USB 摄像头，`ffmpeg` / OpenCV / `v4l2` 直接就能读。
- **深度/IR 必须走 SDK** —— 私有协议，内核不认。
- 两路**互相独立**，可以分别打开，互不干扰。

补充：`2bc5:0403` 这个深度设备的 USB 描述里用的是 `Vendor Specific Class`，带两个 bulk IN 端点；Orbbec 的 udev 规则会给它建软链：

```
/dev/astra_pro -> bus/usb/001/056
```

## 3. 设备自报身份（由 SDK 读出）

`HelloOrbbec`（官方预编译 aarch64 样例）输出：

```
Device name   : Astra Pro
pid           : 1027   (0x0403)
vid           : 11205  (0x2bc5)
firmware      : RD108C-009
serial        : 17121620113
ConnectionType: USB2.0
sensor types  : IR + Color + Depth
```

> 注意：型号叫 **Astra Pro Plus**，但设备上报的 name 是 `Astra Pro`，PID 是 `0x0403`。
> 这很正常 —— Astra Pro Plus 属 **PrimeSense/PS1080 系**（老世代），
> 所以 **只能用 SDK v1**，**切勿换成 OrbbecSDK v2**（v2 已不支持该老机型）。

## 4. 彩色节点与可用格式（实测）

`v4l2-ctl --list-devices` 里彩色那一项显示为：

```
Astra Pro HD Camera: Astra Pro  (usb-0000:01:00.0-1.1.1):
        /dev/video0
        /dev/video1
        /dev/media4
```

（`video1` 是同一 UVC 设备的元数据节点，抓图用 `video0`。）

`v4l2-ctl -d /dev/video0 --list-formats-ext` 实测支持：

| 格式 | 分辨率 | 帧率 |
|---|---|---|
| **YUYV**（未压缩） | 1280x720 | 10 / 5 fps |
| | 640x480 | 30 / 15 |
| | 352x288 · 320x240 · 176x144 · 160x120 | 30 / 15 |
| **MJPG**（压缩） | **1280x720** | **30 / 15** |
| | 640x480 | 30 / 15 |
| | 352x288 | … |

**推荐：`MJPG @ 1280x720@30`** —— YUYV 在 720p 下只有 10fps，MJPG 能到 30fps 且带宽小得多（USB2.0 上尤其重要）。

## 5. 驱动 / 用户态栈现状

| 组件 | 状态 |
|---|---|
| 内核 `uvcvideo` | 已加载，正持有彩色设备（`refcount=1`） |

| Orbbec 私有驱动 | 已含 `libPS1080.so`（PrimeSense 系） |
| Orbbec SDK | **手动部署**在 `/opt/orbbec`（见 `docs/03`） |
| udev 规则 | 已装（见下） |

### udev 规则

部署 SDK 后执行了官方脚本 `install_udev_rules.sh`，规则落在
`/etc/udev/rules.d/99-obsensor-libusb.rules`，其中本机相关的一条：

```
SUBSYSTEMS=="usb", ATTRS{idVendor}=="2bc5", ATTRS{idProduct}=="0403",
  MODE:="0666", OWNER:="root", GROUP:="video", SYMLINK+="astra_pro"
```

规则文件里同时覆盖了 Astra / Astra+ / Femto / Gemini 全系列，属于官方通用清单，**不用改动**。

## 6. 排查环境时常用命令

```bash
lsusb | grep -i orbbec                      # 确认两个设备都在
v4l2-ctl --list-devices                     # 节点归属
v4l2-ctl -d /dev/video0 --list-formats-ext  # 彩色支持的格式/帧率
ls -l /dev/astra_pro                        # 深度设备软链
ls -l /dev/video*                           # 注意 video0/1 是彩色，其余是树莓派自带的 ISP/codec
fuser -v /dev/video0                        # 谁占着彩色（占用会导致抓帧失败）
```

> 树莓派自身还有一堆 `bcm2835-codec` / `bcm2835-isp` 的 `video10~video23`，
> **别被它们迷惑** —— 相机只有 `video0` / `video1`。
