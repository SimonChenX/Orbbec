# Orbbec Astra Pro Plus · 采集 / 转发 / 分析与监控

内网一套完整的 Orbbec Astra Pro Plus（彩色 + 深度 + 红外）采集与可视化系统：
**树莓派瘦采集端**（只读设备、只转发）→ **服务器聚合端**（渲染 / Web / 分析）。

* 网页监控：`http://camera.internal.jiayouexp.com`（内网）
* 也支持**本机直连**：相机直接插在服务器上，走回环，完全不占网络（见 §5）

---

## 1. 架构

```
┌──────────────────── 采集端（树莓派 / 或本机）────────────────────┐
│  ob-relay (Python)                                              │
│   ├─ 彩色：ffmpeg 读 /dev/video0，原生 MJPEG **透传**（零 CPU/零画质损失）│
│   ├─ 传感器：Orbbec SDK v1（ctypes 绑定，零编译）                │
│   │     depth 320x240@30  或  ir 640x480@30（二选一，见 §3）      │
│   └─ 深度/红外原始流 zlib 压缩（7~10 倍）                        │
└───────────────┬─────────────────────────────────────────────────┘
                │ OBF1 协议（TCP，28 字节大端定长头 + payload）
                │ 三条流各一条连接 + 一条控制通道（反向复用）
┌───────────────▼──────────────── 聚合端（服务器 192.168.5.20）──────┐
│  ob-hub (Go)                                                    │
│   ├─ :9501 采集入站（PSK/HMAC 鉴权，ufw 只放行内网网段）          │
│   ├─ 深度 uint16 → 伪彩 JPEG     红外 Y10 → 灰度（直方图分位拉伸）│
│   ├─ :9500 HTTP（只监听 127.0.0.1，nginx 反代）                   │
│   └─ 控制通道：下发相机/码流参数到采集端                          │
│                                                                  │
│  ob-pose (Python + mediapipe)：彩色 → 33 关键点 → POST /api/pose  │
└───────────────┬─────────────────────────────────────────────────┘
                │ nginx 反代
┌───────────────▼─────────────────────────────────────────────────┐
│  前端（静态页）：双画面 + 状态栏 + 参数设置 + 鼠标取深度 + 骨骼叠加 │
└─────────────────────────────────────────────────────────────────┘
```

**三条铁律**（树莓派算力弱，全按这几条设计）：
1. **绝不阻塞采集** —— 采集线程 → 最新帧队列(容量1) → 发送线程；网络慢只丢帧，不反压相机。
2. **按流分连接** —— 深度卡不拖累彩色。
3. **服务器/网络挂了能降级** —— 采集端本地 viewer 保留，可自看。

## 3. ⚠️ 这台设备的硬约束（买之前/写代码前务必先看）

全部由**真实抓帧实测**得出，不是查手册 —— 这台设备的档位表和实际能力**完全对不上**。

| 结论 | 依据 |
|---|---|
| **深度只有 320x240 可用** | 640x480 有效像素仅 **2%**、1280x1024 仅 4.6%；320x240 是 **68~75%**。已排除带宽因素（把彩色降到 640x480 再测反而更差） |
| **红外只有 640x480 出图** | 320x240 档位在列表里、能起流，但**永远等不到 frameset（0 帧）**；640x480 是 29fps |
| **深度与红外不能同时出图** | 两者共用同一个 IR 传感器。两条流都 enable 时：深度 29fps 正常、**IR 恒为 0 帧** → 做成二选一 |
| **红外测不了温度** | 850nm 近红外**补光相机**，拍反射率（等于黑白相机），设备内**无热像传感器**。要温度必须另配热像仪 |
| **深度原始值是「厘米」** | SDK 报 `valueScale=1.0`，但那样"人 61mm"不可能；用距离比值判定（238/61 ≈ 3.9，与真实场景 3.1m/0.8m 吻合）→ ×10 得毫米。已做成可标定参数 `OB_HUB_DEPTH_MM_PER_UNIT` |
| **彩色原帧本就是正立的** | 深度逐行中位深度的物理判据（俯拍时远端在上、近端在下）+ 用户当场确认 → 彩色/深度**都不旋转**（早期"彩色须转 180°"的结论已推翻） |
| UVC 只有 User Controls | 曝光/增益全自动、不可控。逆光场景靠 `backlight_compensation=3` + `gamma=160` + `brightness=8` 改善（暗部像素 73%→31%） |

## 4. 接口一览

| 路径 | 说明 |
|---|---|
| `/` | 监控页（双画面 + 状态 + 参数设置） |
| `/color.mjpg` `/depth.mjpg` `/ir.mjpg` | MJPEG 流 |
| `/snapshot/{color,depth,ir}.jpg` | 单帧快照 |
| `/api/status` | 状态 JSON（各路 fps/seq/延迟、带宽、采集端上报、骨骼状态） |
| `/api/config` `GET\|POST` | 读/改相机参数与码流参数（POST 仅内网） |
| `/api/depth_at?x=&y=` | 取某像素深度（返回原始值与毫米；坐标是深度图像素坐标） |
| `/api/pose` `GET\|POST` | 骨骼关键点（POST 由侧车写，仅内网） |

前端支持 `?snap=1`（静态模式：每秒拉快照，用于弱网/嵌入/无头截图）
与 `#settings`（直接展开参数设置）。

## 5. 部署

### 5.1 服务器（聚合端）
```sh
cd hub
sh deploy/install.sh          # 装 ob-hub + 生成 PSK + ufw 放行内网 → 9501
# 骨骼分析（可选）
pip3 install mediapipe
#   模型：见 hub/models/README.md（3 个文件，共约 23MB，需走代理下载）
systemctl enable --now ob-pose
```
nginx：把 `tools/ob-hub-proxy.conf` 放到宝塔的 vhost extension 目录，
然后用 **`/www/server/nginx/sbin/nginx -s reload`**（宝塔的 nginx 不走 systemd）。

### 5.2 采集端（树莓派 或 本机直连）
```sh
cd pi/relay
sh deploy/install-relay.sh            # 远程采集：推给服务器
sh deploy/install-relay.sh --local    # 本机直连：OB_RELAY_HOST=127.0.0.1，不占网络
```
依赖：`ffmpeg`、`v4l-utils`、`python3`、对应架构的 Orbbec SDK（树莓派 aarch64 / 服务器 x86_64）。
PSK 必须与服务器 `/etc/default/ob-hub` 的 `OB_HUB_PSK` 一致。

## 6. 关键设计取舍

* **彩色走 UVC 原生透传**：`ffmpeg -c:v copy`，30fps 且 CPU 几乎为零（重编码会吃掉 92% CPU）。
* **深度送原始 uint16、渲染放服务器**：树莓派只搬字节，服务器 56 核做伪彩/统计。
* **控制通道反向复用**：树莓派在防火墙后，服务器连不进去；命令顺着 relay 主动建立的连接下发，
  服务器**不存 SSH 凭据**。通道平时静默 → 两端保活（relay 10s / hub 90s 判死）。
* **骨骼分析放独立进程**：推理依赖重、可能崩，独立进程互不影响，随时可停。
* **深度/红外二选一是硬件限制**，不是设计选择（见 §3）。

## 8. 实测数据（2026-10-14）

| 项 | 值 |
|---|---|
| 彩色 | 1280x720 @30fps（原生透传） |
| 深度 | 320x240 @29.7fps，有效像素 68%，中心 894mm，最近 570mm，最远 2390mm |
| 红外 | 640x480 @26.7fps（切到红外模式时） |
| 骨骼 | 8fps，41ms/帧，33 关键点 |
| 端到端延迟 | 14.6ms |
| 入站带宽 | 深度模式 ~57Mbps；红外模式 ~138Mbps（链路 36MB/s ≈ 288Mbps） |
| 树莓派负载 | 空闲 50~86%，温度 43~47°C，零丢帧 |
